## Задача №1: REST API для поисковика GoSearch

### Архитектурные решения:
- **Пакет `pkg/storage`**:
  - Потокобезопасное хранилище `storage.DB` (`sync.RWMutex`) с инвертированным поисковым индексом `idx map[string][]int` и базой документов `docs map[int]Document`.
  - Реализует методы: `Search(query)`, `Documents()`, `Document(id)`, `Add(doc)`, `Update(doc)`, `Delete(id)`.
  - Автоматическая генерация уникального ID при добавлении документов (`doc.ID <= 0`).
  - По условию задания: при модификации или удалении перестроение поискового индекса не обязательно.
- **Пакет `pkg/api`**:
  - Реализован в ООП-стиле: структура `API` со ссылками на маршрутизатор `mux.Router` и интерфейс хранилища `storage.Interface`.
  - Маршрутизация на базе `github.com/gorilla/mux`.
  - Промежуточное ПО (Middleware):
    - `headersMiddleware`: автоматическая установка заголовка `Content-Type: application/json; charset=utf-8`.
    - `requestIDMiddleware`: генерация/чтение уникального `X-Request-ID`, проброс в контекст запроса `r.WithContext(ctx)` и возврат в заголовках ответа.
    - `loggingMiddleware`: структурированное логирование метода, URI, Request ID и длительности выполнения.

### Спецификация эндпоинтов:

| Метод | Путь | Описание | Код успеха | Ошибки |
| :--- | :--- | :--- | :---: | :---: |
| `GET` | `/api/v1/search?q={query}` | Полнотекстовый поиск документов по запросу | `200 OK` | `400 Bad Request` |
| `GET` | `/api/v1/docs` | Получение полного списка документов | `200 OK` | — |
| `GET` | `/api/v1/docs/{id:[0-9]+}` | Получение одного документа по ID | `200 OK` | `404 Not Found` |
| `POST` | `/api/v1/docs` | Создание нового документа | `201 Created` | `400 Bad Request` |
| `PUT` | `/api/v1/docs/{id:[0-9]+}` | Полное обновление документа по ID | `200 OK` | `400 Bad Request`, `404 Not Found` |
| `DELETE` | `/api/v1/docs/{id:[0-9]+}` | Удаление документа по ID | `200 OK` | `404 Not Found` |

## Задача №3: Модель памяти в Go и глубокий подсчет размера (`size.Of`)

Ссылка на исходный код: https://go.dev/play/p/_an3p5w9qB9

### Исходный код структуры:

```go
type example struct {
    a []int
    b bool
    c int32
    d string
}
```

### 1. Выравнивание и поверхностный размер структуры (`unsafe.Sizeof`):

| Поле | Тип | Размер типа | Выравнивание | Смещение в памяти | Пояснение |
| :--- | :--- | :---: | :---: | :---: | :--- |
| `a` | `[]int` | 24 байта | 8 байт | **0 .. 23** | Заголовок слайса: указатель `Data` (8B) + `Len` (8B) + `Cap` (8B) |
| `b` | `bool` | 1 байт | 1 байт | **24** | Логический флаг |
| *padding* | — | 3 байта | — | **25 .. 27** | Выравнивание поля `c int32` требует адрес, кратный 4 (28) |
| `c` | `int32` | 4 байта | 4 байта | **28 .. 31** | 32-битное целое число |
| `d` | `string` | 16 байт | 8 байт | **32 .. 47** | Заголовок строки: указатель `Data` (8B) + `Len` (8B) (32 кратно 8) |

**Итоговый размер самой структуры `unsafe.Sizeof(example)` = 48 байт.**

---

### 2. Подстановка значений вместо `?` и расчет `size.Of`:

```go
ex := example{
    a: []int{1, 2, 3}, // 24 байта (заголовок) + 3*8 байт (массив в куче) = 48 байт
    b: true,           // 1 байт (внутри структуры)
    d: "1234",         // 16 байт (заголовок) + 4 байта (буфер строки) = 20 байт
} // unsafe.Sizeof: 48 байт | size.Of: 76 байт

ex1 := example{
    a: []int{1, 2, 3}, // 24 байта (заголовок) + 3*8 байт (массив в куче) = 48 байт
    b: true,           // 1 байт (внутри структуры)
    d: "1234",         // 16 байт (заголовок) + 4 байта (буфер строки) = 20 байт
    c: 100,            // 4 байта (внутри структуры)
} // unsafe.Sizeof: 48 байт | size.Of: 76 байт
```

### 3. Объяснение результата `size.Of(ex) == 76` и `size.Of(ex1) == 76`:

1. Библиотека `github.com/DmitriyVTitov/size` вычисляет **глубокий размер (Deep Size)**:
   - Размер самой структуры `example`: **48 байт** (включая внутренний padding 3 байта и место под поле `c int32`).
   - Память под массив среза `ex.a`: 3 элемента `int` по 8 байт каждый = **24 байта**.
   - Память под символы строки `ex.d`: 4 символа ASCII по 1 байту = **4 байта**.
   - Сумма: `48 + 24 + 4 = 76 байт`.
2. **Почему `ex1` занимает ровно столько же (76 байт)?**
   - В Go структура представляет собой **статически скомпилированный блок памяти фиксированного размера**.
   - Поле `c int32` присутствует в структуре **всегда**: и в `ex`, и в `ex1`. В переменной `ex` оно не указано в литерале инициализации и содержит нулевое значение `0` (`zero value`), занимая свои 4 байта на смещении `28..31`. В `ex1` оно содержит `100` на том же самом смещении.
   - Скалярный тип `int32` не создает никаких аллокаций в куче и не содержит указателей. Поэтому глубокий размер `size.Of(ex1)` в точности равен `size.Of(ex) = 76 байт`.

## Инструкция по запуску

### Запуск REST API сервера:

```bash
go run ./lessons/13-api/homework-13/cmd/server/main.go
```

Сервер начнет слушать порт `:8080`. Примеры запросов:

```bash
# 1. Поиск документов
curl -s "http://localhost:8080/api/v1/search?q=concurrency" | jq

# 2. Получение всех документов
curl -s "http://localhost:8080/api/v1/docs" | jq

# 3. Получение документа по ID
curl -s "http://localhost:8080/api/v1/docs/1" | jq

# 4. Добавление нового документа
curl -s -X POST "http://localhost:8080/api/v1/docs" \
     -H "Content-Type: application/json" \
     -d '{"title":"Docker Guide","url":"https://docs.docker.com","body":"Containerization basics"}' | jq

# 5. Обновление документа
curl -s -X PUT "http://localhost:8080/api/v1/docs/1" \
     -H "Content-Type: application/json" \
     -d '{"title":"Tutorial: Advanced Go","url":"https://go.dev/doc/tutorial","body":"Updated text"}' | jq

# 6. Удаление документа
curl -s -X DELETE "http://localhost:8080/api/v1/docs/1" | jq
```
