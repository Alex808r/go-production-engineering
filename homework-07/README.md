## Задача №1: Модульные тесты `sort.Ints()` и `sort.Strings()`

Реализовано в пакете [`pkg/sorts/sorts_test.go`](file:///Users/user/workspace/golang_projects/go-core-4/go_course_4/homework-07/pkg/sorts/sorts_test.go).

### 1. Простой тест для `sort.Ints()`
Проверяет базовый контракт сортировки целочисленного среза, содержащего положительные числа, отрицательные значения и ноль:
```go
func TestSortInts(t *testing.T) {
	data := []int{42, -5, 0, 17, -100, 8, 3}
	want := []int{-100, -5, 0, 3, 8, 17, 42}

	sort.Ints(data)

	if !sort.IntsAreSorted(data) {
		t.Errorf("sort.IntsAreSorted(data) = false, want true")
	}
	if !reflect.DeepEqual(data, want) {
		t.Errorf("sort.Ints() got %v, want %v", data, want)
	}
}
```

### 2. Табличный тест для `sort.Strings()`
Использует идиоматичную структуру `tests := []struct { name string; in []string; want []string }` с запуском подтестов через `t.Run(tt.name, ...)`. Покрыты ключевые граничные и особые случаи:
1. **Пустой срез (`[]string{}`)** — проверка отсутствия паники.
2. **`nil` срез** — корректная обработка неинициализированного среза.
3. **Один элемент** — тривиальный случай сортировки.
4. **Уже отсортированный срез** — проверка стабильности порядка.
5. **Срез в обратном порядке** — максимальное количество перестановок.
6. **Дубликаты** — сохранение всех повторяющихся элементов.
7. **Регистрозависимость (ASCII-порядок)** — заглавные буквы (`'A'` = 65) идут перед строчными (`'a'` = 97).
8. **Unicode (кириллица UTF-8)** — побайтовое лексикографическое сравнение многобайтовых рун.
9. **Общие префиксы разной длины** — (`"test"`, `"testcase"`, `"tester"`, `"testing"`).
10. **Спецсимволы, пробелы и цифры** — проверка нестандартных символов.

> [!IMPORTANT]
> В каждом подтесте создается изолированная копия среза (`copy(input, tt.in)`), чтобы мутирующая функция `sort.Strings` не изменяла эталонные данные тестовой таблицы при повторных прогонах.

## Задача №2: Бенчмарки производительности `sort.Ints()` vs `sort.Float64s()`

Бенчмарки замеряют скорость сортировки неотсортированных массивов случайных чисел для размеров $N \in \{10, 100, 1\,000, 10\,000\}$ с замером аллокаций памяти (`b.ReportAllocs()`).

### Результаты замеров (Apple M1 Pro, Go 1.21+):

| Функция | Размер $N$ | Кол-во операций | Время выполнения (`ns/op`) | Память (`B/op`) | Аллокации (`allocs/op`) |
| :--- | :---: | :---: | :---: | :---: | :---: |
| `sort.Ints` | **10** | 3 868 743 | **52.8 ns/op** | 0 B/op | 0 allocs/op |
| `sort.Float64s` | **10** | 3 252 450 | **42.1 ns/op** | 0 B/op | 0 allocs/op |
| `sort.Ints` | **100** | 184 539 | **626.5 ns/op** | 0 B/op | 0 allocs/op |
| `sort.Float64s` | **100** | 147 826 | **787.4 ns/op** | 0 B/op | 0 allocs/op |
| `sort.Ints` | **1 000** | 12 744 | **9 645 ns/op** | 0 B/op | 0 allocs/op |
| `sort.Float64s` | **1 000** | 7 758 | **16 249 ns/op** | 0 B/op | 0 allocs/op |
| `sort.Ints` | **10 000** | 286 | **420 378 ns/op** | 0 B/op | 0 allocs/op |
| `sort.Float64s` | **10 000** | 213 | **572 177 ns/op** | 0 B/op | 0 allocs/op |

### Глубокий сравнительный анализ:

1. **Разница во времени выполнения:**
   - При малом размере $N=10$ время практически идентично (сортировка вставками insertion sort).
   - На средних и больших массивах ($N \ge 1000$) **`sort.Ints` работает быстрее `sort.Float64s` на ~36–68%** (9.6 µs против 16.2 µs при $N=1000$).
2. **Почему `sort.Ints` быстрее `sort.Float64s`:**
   - **Специфика стандарта IEEE 754 и `NaN`:** В математике чисел с плавающей точкой значение `NaN` (Not a Number) не равно ничему, включая себя (`NaN == NaN` возвращает `false`), а выражения `NaN < x` и `NaN > x` всегда ложны. Чтобы алгоритм сортировки (pdqsort) не входил в бесконечные циклы или не нарушал транзитивность, `sort.Float64s` обязан реализовывать специальное сравнение с учетом `NaN` (выталкивание `NaN` в конец или проверка битовых масок).
   - **Инструкции процессора:** Сравнение целых чисел (`CMP` + условный переход или условное перемещение `CSEL`) на архитектурах ARM64 / x86_64 выполняется за 1 такт ALU с отличным предсказанием ветвлений (Branch Predictor). Сравнение чисел с плавающей точкой требует работы регистров FPU/SIMD и имеет большую латентность конвейера.
3. **Память и аллокации:**
   - Обе функции показывают **`0 B/op` и `0 allocs/op`**, поскольку стандартные алгоритмы сортировки Go сортируют срез **на месте (in-place)** без выделения дополнительной динамической памяти в куче (heap).

## Инструкции по запуску тестов, бенчмарков и сбору покрытия


### 2. Запуск тестов без кэширования результатов (`-count 1`):
```bash

```

### 3. Запуск тестов с подсчетом процента покрытия кода (`-cover`):
```bash
go test -cover ./homework-07/...
```

### 4. Запуск бенчмарков сортировки с замером памяти (`-benchmem`):
```bash
go test -v -bench=. -benchmem -run '^$' ./homework-07/pkg/sorts/...
```
> Флаг `-run '^$'` отключает запуск обычных тестов, выполняя только замеры производительности.

### 5. Генерация HTML-отчета о покрытии кода:
```bash
go test -coverprofile=coverage.out ./homework-07/pkg/index/...
go tool cover -html=coverage.out
```
