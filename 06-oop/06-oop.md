# 06-oop — Объектно-ориентированное программирование в Go: методы, композиция и DIP

В данной директории изучаются принципы ООП в Go: отсутствие классов и наследования, замена наследования композицией и встраиванием (`embedding`), паттерны конструкторов (`New`) и инверсия зависимостей (`Dependency Inversion Principle`).

## 🔍 Ключевые концепции

1. **Композиция вместо наследования (`3-embedding`):**
   - Go не поддерживает классическое наследование классов.
   - Поля и методы анонимно встраиваемой структуры "продвигаются" (method promotion) на верхний уровень:
     ```go
     type Server struct {
         Logger // Встраивание
     }
     ```

2. **Инверсия зависимостей (DIP) и слабая связанность (`2-dip`):**
   - Бизнес-логика зависит от абстракций (интерфейсов), а не от конкретных реализаций (БД или stdout).
   - В тестах зависимость легко подменяется на заглушку в памяти (`&MemLogger{}`).

3. **Нюансы встраивания интерфейсов:**
   - Если структура встраивает интерфейс, но соответствующее поле равно `nil`, вызов метода интерфейса приводит к панике `nil pointer dereference`. Необходимо либо переопределять метод структуры, либо инициализировать поле конкретной реализацией.

4. **Функции-конструкторы (`4-constructor`):**
   - Создание объектов через функции вида `New(...) (*Type, error)` гарантирует корректное начальное состояние и инварианты структуры.
