# git-workflow

Перед применением прочитай [общие правила](../../../AGENTS.md).

1. Прочитай раздел 2 AGENTS.md. Проверь git status, diff и staged diff; отдели свои изменения от пользовательских и untracked-файлов.
2. Не меняй ветку, не создавай PR, не коммить и не отправляй изменения по собственной инициативе.
3. Перед запрошенным коммитом выполни status и diff --stat, подготовь Conventional Commit с точным scope и соблюди гейт подтверждения из AGENTS.md.
4. Добавляй только согласованные пути, не используй git add . для смешанного дерева. Не отменяй чужие изменения и не делай amend/reset/rebase/force push без отдельного указания.
5. Публикация не подразумевается разрешением на commit. Целевую ветку и remote проверяй фактически, не копируй stage/production из другого проекта.
6. Для многострочного описания PR используй файл или структурированный аргумент; проверь итоговый текст и фактический результат разрешённой операции.
