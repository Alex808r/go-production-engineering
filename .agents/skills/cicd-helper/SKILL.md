# cicd-helper

Перед применением прочитай [общие правила](../../../AGENTS.md).

1. Прочитай .github/workflows/ci.yml и соответствующие go.mod. Определи текущий remote, SHA и конкретный run/job; определи CI-платформу по конфигурации репозитория.
2. Текущий workflow проверяет корневой модуль; wallet требует самостоятельной проверки. continue-on-error у security scan учитывать отдельно от обязательных шагов.
3. Используй доступный connector/CLI и его --help. При отсутствии доступа разберись с локальным YAML и предоставленными логами, явно обозначив непроверенное состояние CI.
4. Для падения прочитай сообщение и относящийся код: различай дефект, недоступный toolchain, сеть/runner и отсутствующий сервис.
5. Наблюдение ограничивай порученным run и сроком; при смене SHA проверь, какой run актуален. Ошибка API, canceled, skipped и manual не равны успеху.
6. Retry — только в рамках разрешённого действия после подтверждённого временного сбоя; не перезапускай deploy/publish или весь pipeline вслепую. Не выполняй merge, push или публикацию по поручению только на диагностику.
7. В отчёте дай SHA, run/job, статус обязательных и необязательных проверок, ссылку и окончание наблюдения.
