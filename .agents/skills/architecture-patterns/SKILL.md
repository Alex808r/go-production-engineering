# architecture-patterns

Перед применением прочитай [общие правила](../../../AGENTS.md).

1. Прочитай AGENTS.md, целевой go.mod, входную точку и полный путь вызова до хранилища.
2. Не навязывай одинаковые каталоги всем сервисам: wallet/internal и lynks/*/pkg имеют разные структуры.
3. HTTP-слой разбирает запрос и преобразует ошибки; бизнес-инварианты остаются в service/domain.
4. Интерфейс вводи у потребителя при реальной необходимости; домен не импортирует HTTP или драйвер БД.
5. Перед изменением операции установи транзакционные границы, блокировки, идемпотентность, поведение при повторе и отмене context.
6. Публикация события и запись в БД требуют явного решения об атомарности; учитывай риск потери события при публикации после commit.
7. Сохраняй публичный контракт, порядок эффектов и существующие ошибки. Чужой API проверяй по установленной версии и документации; недоступность MCP не блокирует чтение локальных исходников.
8. Не вводи DDD/CQRS или новые зависимости ради самого паттерна. Для учебных заданий сохраняй сигнатуры и не меняй лекционные примеры.
