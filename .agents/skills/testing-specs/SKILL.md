# testing-specs

Перед применением прочитай [общие правила](../../../AGENTS.md).

1. Прочитай целевой go.mod, код, существующие тесты и Makefile. Корневой go test не охватывает wallet.
2. Для поведения проверяй наблюдаемый контракт: успех, ошибочные входы, пограничные случаи, ошибки зависимостей; для изменений хранения — факт записи и отсутствие частичных эффектов при ошибке.
3. Используй testing и принятые в пакете средства; httptest для HTTP, t.TempDir/t.Cleanup для ресурсов. Не привязывай тест только к внутреннему порядку вызовов.
4. Начинай с затронутых пакетов, расширяй по scope. Команды из корня: go test ./... и go build ./.... В wallet отдельно: go test -v ./... и go build ./....
5. При конкурентных изменениях запускай -race; для wallet предусмотрены make test-race и make test-concurrency. Для lessons/10-concurrency: go test -race ./lessons/10-concurrency/....
6. До интеграционных тестов прочитай setup: выясни необходимость БД/Redis/Kafka и наличие in-memory альтернатив. Docker не запускать автоматически.
7. Не правь go.mod ради доступного toolchain; сообщи о недоступной версии, сети, сервисе или существующем синтаксическом дефекте. Сохраняй полный исход проверки, skipped не считать успехом.
8. Не добавляй тесты, повторяющие реализацию, для косметических изменений документации.
