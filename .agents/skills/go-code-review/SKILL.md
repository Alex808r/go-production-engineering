# go-code-review

Перед применением прочитай [общие правила](../../../AGENTS.md).

1. Определи границы ревью и прочитай diff, новые файлы, вызывающий код и относящиеся тесты.
2. Первый проход: сверить каждый критерий задачи с кодом и проверкой; второй: контракты и конвенции каждого изменённого компонента.
3. Проверь typed nil, errors.Is/As, shadowing, закрытие Body/Rows, отмену context, завершение горутин и владельца закрытия каналов.
4. Проверь map/slice под конкурентным доступом, порядок mutex, транзакции, повторы, rollback и ошибки после частичного эффекта.
5. Оцени ответственность методов, лишние обёртки и зависимость от чужих внутренних данных. Оценивай код по идиомам Go и существующим контрактам.
6. Замечание должно описывать воспроизводимый сценарий, влияние, файл/строку и предлагаемое исправление. Предположение явно помечать.
7. При запросе только ревью не правь файлы. Если находок нет, укажи границы и реально выполненные проверки; саморевью не называть независимым ревью.
8. При ревью новых или изменённых структур проверь выполнение правила `fieldalignment` из раздела 3 AGENTS.md: фактический запуск, размер структуры и GC pointer bytes, причины оставленных предупреждений и риски перестановки полей.
